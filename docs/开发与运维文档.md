# SVC Admin 开发与运维文档

> 版本：2026-10-25
> 适用系统：Ubuntu 24.04 LTS（单机，apt 原生部署，不使用容器）
> 代码位置：本仓库（`svc-admin/`），部署后位于服务器 `/opt/svcadmin`

---

## 1. 项目概览

在一台 Ubuntu 24.04 单机上提供并统一管理以下服务，全部通过自研 Web 面板配置，不依赖第三方管理界面：

| 服务 | 实现 | 说明 |
|---|---|---|
| FTP | pure-ftpd-mysql | 虚拟用户存 MariaDB，FTPS，配额/限速 |
| DNS 代理 | dnsmasq | 上游转发、缓存、本地 A/CNAME、域名屏蔽 |
| RADIUS | FreeRADIUS 3.2.5 + MySQL 后端 | 用户/组/NAS/会话，radtest 自测 |
| Syslog | rsyslog + ommysql | 远程接收、规则过滤、入库检索 |
| SNMP | net-snmp snmpd | 本机代理配置 + 被监控主机采集（内存/磁盘/接口流量） |
| NTP | chrony | 上游同步，对内授时（UDP 123） |
| 网络配置 | netplan + systemd-networkd | 图形化改 DHCP/静态地址，带 90 秒自动回滚 |

另外提供：总览仪表盘（CPU/内存/磁盘/负载/网络实时曲线）、账号与角色（管理员 / 只读）、审计日志、配置备份与失败回滚。

**设计原则**

- 面板只做"编排 + 渲染 + 审计"，真正的落盘与重启交给 root 助手；
- 每个服务只由面板"拥有"少量配置文件，不接管整份系统配置；
- 所有变更：渲染 → 校验 → 备份 → 原子安装 → 重启 → 健康检查 → 失败自动回滚；
- 只读角色在服务端拦截所有写请求，不依赖前端隐藏。

## 3. 架构

```
浏览器 ──HTTPS 443──→ Nginx（TLS / HSTS）
                        └─→ uvicorn 127.0.0.1:8080（svcadmin 用户，FastAPI）
                              ├─→ MariaDB（svcadmin / radius / logs）
                              ├─→ /var/lib/svcadmin/staging    写待应用配置
                              └─→ sudo -n /usr/local/sbin/svcadmin-apply <service>
                                    备份 → 原子安装 → 配置校验 → 重启 → 健康检查 → 失败回滚
                                    ├─ dnsmasq
                                    ├─ pure-ftpd-mysql
                                    ├─ freeradius
                                    ├─ rsyslog
                                    ├─ snmpd
                                    └─ chrony

网络配置单独走 /usr/local/sbin/svcadmin-net（apply/confirm/pending/show），
带 90 秒自动回滚计时器，rollback 仅 root 可直接执行。
```

### 信任边界

- 面板进程以无 shell 的 `svcadmin` 用户运行，只能写 `/var/lib/svcadmin/staging`；
- sudoers 只放行两个固定二进制，且 `svcadmin-net` 只放行 `apply|confirm|pending|show` 四个子命令；
- 所有目标路径在助手内按服务白名单校验（`/etc/dnsmasq.d/`、`/etc/pure-ftpd/`、`/etc/rsyslog.d/`、`/etc/snmp/`、`/etc/chrony/`）；
- 助手拒绝符号链接、非普通文件、超过 512KB 的源文件。

## 5. 安装与升级

### 5.1 首次安装

```bash
cd /root/svc-admin
sudo bash deploy/install.sh
```

`install.sh` 的主要步骤（幂等，可重复执行）：

1. 安装依赖包：nginx、mariadb-server、python3-venv、dnsmasq、pure-ftpd-mysql、freeradius(+mysql)、rsyslog-mysql、snmpd、snmp、chrony、logrotate；禁用 `systemd-timesyncd`
2. 设置时区 Asia/Shanghai；写入 MariaDB `default-time-zone='+08:00'`
3. 创建系统用户：`svcadmin`（面板）、`ftpuser`（uid/gid 2001，FTP 虚拟用户归属）；`svcadmin` 加入 `adm`、`ftpuser` 组
4. 复制代码、创建 venv、安装 Python 依赖
5. 生成密钥写入 `/etc/svcadmin/svcadmin.env`（DB 密码、会话密钥、rsyslog DB 密码、时区）
6. 建库建表：`svcadmin` / `radius` / `logs`；导入 FreeRADIUS 官方 SQL schema 与 rsyslog 表结构；创建受限 DB 用户
7. 配置 FreeRADIUS：启用 `sql` 模块、写入 DB 凭据、开启 `read_clients`、注释 MySQL TLS 证书项；清空自带 `clients.conf`（客户端统一来自 `nas` 表）
8. 配置 rsyslog：禁用 dbconfig 残留配置，添加 AppArmor 本地覆盖（允许连 MariaDB socket）
9. 配置 dnsmasq：启用 `conf-dir`，关闭 systemd-resolved 的 53 stub，`/etc/resolv.conf` 指向 127.0.0.1；查询日志归 `dnsmasq:adm 0640` 并配置 logrotate + systemd drop-in
10. 生成两张自签证书（面板、FTP）
11. 安装助手、sudoers、systemd 单元、Nginx 站点；放通 UFW（53/161/1812/1813/514/123）
12. 初始化管理员（随机密码打印一次）并以 `svcadmin` 身份执行 `bootstrap`：为六个服务生成并应用初始配置

### 5.2 升级应用

```bash
# 上传新代码到 /root/svc-admin 后
cp -a /root/svc-admin/app/. /opt/svcadmin/app/
cp /root/svc-admin/requirements.txt /opt/svcadmin/
/opt/svcadmin/venv/bin/pip install -q -r /opt/svcadmin/requirements.txt
systemctl restart svcadmin
```

> 新表由 `init_db()` 自动创建；`admin_user.role`、`snmp_host.mem_*` 等列由 `db._migrate()` 启动时自动补齐。

### 5.3 常用命令

```bash
systemctl status svcadmin nginx dnsmasq pure-ftpd-mysql freeradius rsyslog snmpd chrony
journalctl -u svcadmin -n 200 --no-pager
cd /opt/svcadmin && ./venv/bin/python -m app.cli set-password --username admin --password '新密码'
cd /opt/svcadmin && ./venv/bin/python -m app.cli prune-syslog --days 30
```

## 6. 权限与变更机制

### 6.1 面板侧

- 登录：argon2 哈希 + 签名 Cookie（itsdangerous），HttpOnly / SameSite=Lax / Secure
- CSRF：登录用独立签名 token；会话内 token 校验所有表单
- 登录限速：同 IP 10 分钟内 8 次失败锁定
- 角色：`admin`（可改）/ `viewer`（只读）。中间件对 viewer 的所有 POST 直接返回 303 + 错误提示（白名单：登录、退出、修改自己密码）

### 6.2 配置落地助手 `svcadmin-apply`

面板把渲染好的文件与 manifest 写到 `staging/<service>/`：

```json
{
  "service": "dns",
  "files": [
    {
      "dest": "/etc/dnsmasq.d/svcadmin.conf",
      "src": "00-svcadmin.conf",
      "mode": "0644",
      "owner": "root:root"
    }
  ],
  "validate": [["dnsmasq", "--test", "-C", "{staged}"]],
  "restart": ["systemctl", "restart", "dnsmasq"],
  "health": [["systemctl", "is-active", "dnsmasq"]],
  "health_ports": [53],
  "actions": []
}
```

助手流程：

1. 服务名与目标路径白名单校验；源文件必须是 staging 内普通文件
2. 备份现有配置到 `/var/lib/svcadmin/backups/<service>/<时间戳>/`
3. 原子安装（同目录临时文件 + rename）
4. 执行校验命令（`{staged}` 指向配置副本；对受 AppArmor 限制的服务放在其配置目录）
5. 重启 + 健康检查（systemd 状态 + 端口；`"123/udp"` 表示 UDP）
6. 任一步失败：还原备份 → 重启 → 返回 JSON 错误给面板

各服务的校验方式：

| 服务 | 校验命令 |
|---|---|
| DNS | `dnsmasq --test -C <staged>` |
| NTP | `chronyd -p -f <staged>`（副本放 `/etc/chrony/.svcadmin-validate.conf`，校验后删除） |
| FTP / Syslog / SNMP / RADIUS | 无独立校验，依赖重启 + 健康检查 + 失败回滚 |

### 6.3 网络助手 `svcadmin-net`

```
apply    读取 staging/network/spec.json → 备份 netplan → 写 60-svcadmin.yaml
         → netplan generate 校验 → netplan apply → 启动 90 秒回滚计时器
confirm  取消计时器，保留配置
pending  查询是否有待确认回滚
show     返回是否由面板接管、当前模式
rollback <备份目录>  还原并应用（仅 root 直接执行，sudo 不放行）
```

回滚计时器由 `systemd-run --on-active=90` 触发；若新地址导致失联，90 秒后自动恢复。

## 7. 服务模块

### 7.1 FTP（pure-ftpd-mysql）

- 虚拟用户存 `svcadmin.ftp_user`，密码为 SHA-512 crypt（`openssl passwd -6`）
- 家目录固定 `/srv/ftp/<用户名>`，uid/gid 2001，`ChrootEveryone`
- 面板生成 `/etc/pure-ftpd/conf/*`（TLS、被动端口、连接数等）与 `/etc/pure-ftpd/db/mysql.conf`
- 证书路径为编译期固定值 `/etc/ssl/private/pure-ftpd.pem`（不可在面板修改）
- 面板能力：用户增删改（配额 / 限速 / 启停）、全局设置、登录自测（ftplib，密码不保存）
- 注意：删除用户保留家目录；保存用户会触发一次服务重启以创建家目录

### 7.2 DNS（dnsmasq）

- 面板拥有 `/etc/dnsmasq.d/svcadmin.conf`：上游、按域名分流、本地 A/CNAME、域名屏蔽、缓存、查询日志
- 变更使用 **restart**（SIGHUP 不重读配置）
- 查询日志 `/var/log/dnsmasq.log`：`dnsmasq:adm 0640`，logrotate 每周 8 份；dnsmasq 启动后由 drop-in 修正权限
- 面板能力：全部配置项、解析测试（dnspython 查 127.0.0.1）、查询日志（最新在前）
- 注意：与 `systemd-resolved` 的 53 端口冲突已在安装时处理；解析上游在面板配置，系统 `/etc/resolv.conf` 固定指向 127.0.0.1

### 7.3 RADIUS（FreeRADIUS + SQL）

- 数据库 `radius`，使用官方 schema；`mods-enabled/sql` 启用，`read_clients = yes`
- 自带 `clients.conf` 已清空，NAS 客户端只来自 `nas` 表；新增/修改 NAS 后自动重启服务
- 用户密码以 `Cleartext-Password` 存储（PAP/CHAP 需要）
- 面板能力：用户（检查/回复属性按 `属性 = 值` 行编辑）、组、NAS、在线会话、radtest 自测
- 自测客户端：面板自动维护 `127.0.0.1` 的 NAS 行（密钥保存在 `service_config`）

### 7.4 Syslog（rsyslog → MariaDB）

- 面板拥有 `/etc/rsyslog.d/50-svcadmin.conf`：远程接收（UDP/TCP 514，`AllowedSender` 限制网段）、丢弃/转发规则、ommysql 入库
- 表结构见 `deploy/sql/01-logs.sql`；DB 用户 `rsyslog@localhost` 仅有 INSERT/SELECT
- AppArmor：`/etc/apparmor.d/local/usr.sbin.rsyslogd` 放行 unix socket
- 面板能力：接收网段、规则、检索分页、保留天数与清理、实时 tail JSON
- 注意：rsyslog 进程启动时会缓存时区，改系统时区后需重启

### 7.5 SNMP（snmpd + 主机监控）

**本机代理**：面板生成 `/etc/snmp/snmpd.conf`（v2c 团体名与来源网段、v3 用户 SHA/AES、Trap 目标）。v3 口令变更通过重启重建 `createUser`，助手会清理 `/var/lib/snmp/snmpd.conf` 持久化文件。

**被监控主机**（`snmp_host`）：

- 支持 v2c / v3（authPriv SHA+AES），每 60 秒轮询
- 采集：`sysDescr/sysName/sysLocation/sysUpTime`、内存（UCD-SNMP-MIB，回退 HOST-RESOURCES-MIB）、磁盘（UCD dskTable，回退 hrStorage）、接口（IF-MIB）
- 速率 = 相邻两次轮询计数器差值；历史写入 `snmp_ifhistory`，保留 24 小时
- 左侧 SNMP 二级菜单列出所有主机；详情页展示内存/Swap（进度条）、磁盘、接口流量图
- 接口流量图：1/6/24 小时范围，绿色面积=入站、蓝线=出站，悬停十字线，统计列（最新/最小/平均/最大），30 秒刷新，可展开数据表
- 注意：v3 口令明文存库（探测需要），页面不回显；编辑时留空表示不修改

### 7.6 NTP（chrony）

- chrony 替代 systemd-timesyncd；面板生成 `/etc/chrony/chrony.conf`
- 配置项：上游服务器（域名/IP，生成 `pool`）、允许授时网段（`allow`，留空则只作客户端）、本地层级（`local stratum`，0 为不提供本地参考）
- 只有存在 `allow` 才会监听 UDP 123
- 状态页：同步状态（已同步 / 本地时钟 / 未同步）、Stratum、参考源、偏差、时间源列表（`^*` 选中 / `^+` 备选 / `^?` 不可达）
- 首次启动通常需几分钟完成上游选择，期间以本地时钟（Stratum 10）授时
- AppArmor：chronyd 只能读 `/etc/chrony/`，校验副本必须放在该目录

### 7.7 网络配置（netplan）

- 页面显示实时状态（网卡、MAC、IPv4/IPv6、默认路由、DNS）与是否"由面板接管"
- 修改：选网卡 + DHCP 或静态（CIDR + 网关，网关需同网段）
- 首次应用会写 `/etc/cloud/cloud.cfg.d/99-svcadmin-disable-network-config.cfg`，避免 cloud-init 覆盖
- 应用流程与回滚见 6.3；只读账号只能查看

## 8. 面板功能

### 8.1 登录与会话

- `/login`：用户名 + 密码，限速；成功后 12 小时会话
- 所有表单带 CSRF token；退出为 POST
- 403 页面：只读账号越权访问管理页时展示

### 8.2 总览仪表盘

- 后台每 10 秒采样写入 `system_sample`（保留 2 小时）：CPU（/proc/stat 差分）、内存/Swap、磁盘 `/`、负载、全部网卡合计收发速率
- 四张指标卡（CPU/内存/磁盘/负载）+ 最近 15 分钟趋势线；阈值 ≥75% "偏高"、≥90% "过高"
- 网络吞吐曲线：绿色面积=入站、蓝线=出站
- 前端每 10 秒请求 `/dashboard/system.json` 重绘；切回标签页立即刷新
- 下方为六个服务状态卡（含 NTP）与最近操作记录

### 8.3 用户与角色

- `/users` 单页完成所有账号操作：
  - 管理员：账号列表、添加账号、重置任意密码、调整角色、删除账号
  - 只读账号：只看到自己一行与改密输入框（服务端限制只能改自己）
- 约束：至少保留一个管理员；不能删除当前登录账号；改角色需重新登录生效
- 密码：至少 8 位；argon2 存储

### 8.4 审计

- 每次配置应用/账号操作写入 `audit_log`（时间、操作者、服务、动作、详情、结果）
- `/audit` 支持按服务筛选与分页

## 11. 前端与图表规范

- Jinja2 服务端渲染 + HTMX（本地静态文件）+ 手写 CSS，无 Node 构建链
- 图表为原生 SVG + 原生 JS，两种：折线/面积图（接口流量、网络吞吐）与 sparkline（指标卡）
- **配色经过校验**（dataviz 规范）：
  - 分类色（白底）：蓝 `#2a78d6`、橙 `#eb6834`、绿 `#008300`
  - 接口流量：入站绿 `#008300`（面积）、出站蓝 `#2a78d6`（线）
  - 状态色：good `#0ca30c`、warning `#f79009`、critical `#d03b3b`；状态永远带文字标签，不靠颜色单独表达
- 图表细节：2px 线宽、虚线时间刻度、悬停十字线 + 提示框（值在前、序列名在后）、数据表可展开、30 秒自动刷新、窗口缩放重绘

## 12. 时区

四个层面保持一致：

| 层面 | 设置 |
|---|---|
| 系统 | `timedatectl set-timezone Asia/Shanghai` |
| MariaDB | `/etc/mysql/mariadb.conf.d/99-svcadmin-timezone.cnf` → `default-time-zone = '+08:00'` |
| 面板 | `SVCADMIN_TIMEZONE=Asia/Shanghai`（`/etc/svcadmin/svcadmin.env`） |
| rsyslog | 跟随系统；改时区后必须重启进程 |

手工改时区时要同步这四处，并重启所有常驻守护进程（nginx、dnsmasq、pure-ftpd、freeradius、snmpd、chrony、rsyslog、svcadmin）。

## 14. 故障排查

| 现象 | 排查 |
|---|---|
| 面板 502 | `systemctl status svcadmin`；`journalctl -u svcadmin -n 200` |
| 配置保存返回"暂存目录不可写" | `/var/lib/svcadmin/staging` 必须属 `svcadmin`（安装脚本会修正） |
| DNS 不解析 | `systemctl status dnsmasq`；`ss -lunp \| grep :53`；确认 systemd-resolved stub 已关闭 |
| 查询日志 Permission denied | `/var/log/dnsmasq.log` 应为 `dnsmasq:adm 0640`；`svcadmin` 需在 `adm` 组 |
| FTP 登录失败 | `journalctl -u pure-ftpd-mysql`；检查 `/etc/pure-ftpd/conf/MySQLConfigFile` 与 `auth/30mysql` |
| RADIUS 无响应 | `freeradius -XC`；确认 `mods-enabled/sql`、`read_clients`、`nas` 表中有客户端；自带 `clients.conf` 必须为空 |
| 日志不入库 | `aa-status \| grep rsyslog`；检查 `/etc/apparmor.d/local/usr.sbin.rsyslogd` |
| SNMP 无响应 | 团体名 ≥4 位、来源网段、`snmpwalk -v2c -c <团体> 127.0.0.1` |
| NTP 校验失败 | chronyd 受 AppArmor 限制，校验副本必须位于 `/etc/chrony/` |
| NTP 一直"本地时钟" | 首次启动需几分钟完成上游选择；`chronyc sources` 看 `^*` |
| 网络配置应用后失联 | 90 秒后自动回滚；确认在倒计时内到新地址点"保持此配置" |

## 15. 已知限制

- 面板只能在内网/VPN 暴露；自签证书需要浏览器信任
- RADIUS 用户密码与 SNMP v3 口令在库中明文（协议探测需要），DB 仅本机可连
- FTP 删除用户保留家目录；pure-ftpd 证书路径不可在面板修改
- 网络配置只支持 IPv4、单网卡、DHCP 或静态地址（不支持 VLAN/bond/多地址）
- rsyslog ommysql 适合中小日志量；量大需换 Loki/ClickHouse
- SNMP 主机监控按 60 秒轮询，速率是区间平均值；接口数上限 64
- 面板不管理 FreeRADIUS 的 `clients.conf`（固定为空）、不管理 dnsmasq/DNS 之外的系统解析器
